# T-0003: LLM に渡す文脈を、比較の体験を残したままどう絞るか

## 問いの背景
モール API の生レスポンスは大きく、そのまま Bedrock に渡すと入力トークンが膨らむ。件数を削ると比較の体験が損なわれる。

## いまの結論
画面にはフルデータを返し、LLMには直近のツール実行分の全商品を、商品名・価格・モールとレビュー・送料・商品状態に絞って共有する(ADR-0011)。追加する情報は元データにあるキーだけで、欠損を補わない。

実験時の最小フィールドは、全フィールドに対して入力トークンを73.3%減らした。価格だけの最安選択は9/10回だったが、レビュー・送料の条件には必要な情報がなかった。レビュー・送料・商品状態を追加した条件は入力69.0%削減、最安選択23/38回だったため、測定した4構成の暫定標準として採用した。

80文字への短縮や説明文の除外で属性の支持語が失われ、最安候補の見落としも残る。タイトル・説明文の情報保持と数値処理による選択を引き続き検証する。適用後の本番会話の選択成功率と、会話全体の1往復の費用はまだ測っていない。

会話の履歴は直近 6 往復に限って渡す(ADR-0019)。7 往復以上前の条件が使えなくなる影響は、まだ測っていない。
