# T-0003: LLM に渡す文脈を、比較の体験を残したままどう絞るか

- 状態: 継続中(フィールド量と商品選択を実測)
- 試行回数: 7(うち失敗 1・破棄 1)
- 関連 ADR: [ADR-0011](../adr/0011-three-path-data.md)、[ADR-0005](../adr/0005-llm-bedrock-claude-haiku.md)
- 関連: [T-0005](0005-product-count.md)、[T-0004](0004-reply-length-tone.md)

## 問いの背景
モール API の生レスポンスは大きく、そのまま Bedrock に渡すと入力トークンが膨らむ。件数を削ると比較の体験が損なわれる。

## いまの結論
「画面はフル、LLM は直近のツール結果の最小フィールド」の形(ADR-0011)になった。
検索後のLLM呼び出しを測ると、最小フィールドは全フィールドに対して入力トークンを73.3%減らした。価格だけの最安選択は9/10回だったが、レビュー・送料の条件には必要な情報がなかった。
レビュー・送料・商品状態を追加した条件は入力69.0%削減、最安選択23/38回だった。選択の見落としも残り、本番のフィールド構成を決めるには追加の検証が必要である。会話全体の1往復の費用はまだ測っていない。
