# T-0016: ユーザーの反応から、エージェントの返答と提案の質をどう上げるか

- 状態: 継続中
- 試行回数: 6
- 関連 ADR: [ADR-0018](../adr/0018-admin-dashboard-readonly.md)、[ADR-0014](../adr/0014-interaction-events-log.md)、[ADR-0011](../adr/0011-three-path-data.md)、[ADR-0006](../adr/0006-session-memorysaver.md)
- 関連: [T-0015](0015-KEY-ambiguous-shopper.md)(曖昧な発話から絞り込めているかを、本番で測る指標がない)、[T-0003](0003-KEY-llm-context.md)、[T-0005](0005-product-count.md)、[T-0006](0006-KEY-agent-tool-routing.md)

## 問いの背景
構成の良し悪しは、固定した発話と商品によるオフライン評価でしか比べていない(T-0003 回7)。本番の利用者が提案した商品を開いたか、言い直したか、会話をやめたかは記録していない。そのため、ある構成が本番で効いているか、どの発話で外しているかが分からない。

T-0003・T-0005・T-0015 は、決まった指標で構成や振る舞いを比べる問い。この問いは、その指標と評価のケースを本番の反応から得る仕組みそのものを扱う。

## いまの結論
反応を往復と構成に結び付けるログ記録に、Supabase 向け PostgreSQL 保存を追加した。保存・再起動後の読み出し・集計をローカルで確認した（回3）。会話履歴の保存と文脈再開を実際のSupabaseで確認した（回4）。保存したデータを管理者だけが見る画面を、読み取り専用ロールで Supabase を読む形で作り、ローカルで集計 SQL を確認した（回5・回6）。Render・Vercel の接続設定はまだ実施していない。本番の数値はまだ測っていない。商品の購入はモールのサイトで起きるため、Shoppie 側で直接取れる反応は、商品カードのクリック・次の発話・会話のリセット・離脱に限られる。
