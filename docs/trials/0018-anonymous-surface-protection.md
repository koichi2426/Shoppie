# T-0018: 認証のない入口から、運営者の資格情報・費用・記録をどう守るか

- 状態: 継続中
- 試行回数: 3(うち失敗・破棄 0)
- 関連 ADR: [ADR-0019](../adr/0019-llm-history-window.md)、[ADR-0017](../adr/0017-supabase-interaction-events.md)、[ADR-0006](../adr/0006-session-memorysaver.md)
- 関連: [T-0003](0003-KEY-llm-context.md)、[T-0016](0016-KEY-user-feedback-loop.md)、[T-0017](0017-KEY-traffic-capacity.md)

## 問いの背景
API には認証がなく、誰でも `/request-assistance`・`/events`・`DELETE /context` を呼べる([ADR-0006](../adr/0006-session-memorysaver.md))。他人の会話を推測できないことは確かめていた。しかし、その入口から運営者の資格情報、Bedrock の費用、DB への通信、構成判断に使う集計に何が届くかは、まとめて調べていなかった。[T-0003](0003-KEY-llm-context.md) は LLM の入力量、[T-0017](0017-KEY-traffic-capacity.md) は同時接続の性能を扱う問いで、この問いは信頼の境界を越える影響を扱う。

## いまの結論
認証のない入口について、ソースから届く経路のうち、資格情報の漏れと DB 接続の検証不足を塞いだ。費用は [ADR-0019](../adr/0019-llm-history-window.md) で 1 回の入力に上限を付けたが、回数の制限(レート制限)はまだない。

残る要検証の候補は 3 件である。

- ログ行の偽造
- 共有 executor の占有
- AWS 操作ポリシー例の権限昇格

先送りした範囲も 3 つある。

- `context_id` の数の増加
- DB の所有者ロール
- `/_next/image` の枠の消費

どれも、隔離環境での確認か、配備設定の確認が要る。
