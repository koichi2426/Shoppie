# ADR-0013: 試行は ADR と分けて、問いごとの記録(docs/trials/)に残す

- ステータス: 採用
- 日付: 2026-10-05
- 関連: [docs/trials/README.md](../trials/README.md)、[docs/reports/README.md](../reports/README.md)、`.claude/rules/activity-record.md`

## 背景
Shoppie は同じことを何度も試しては戻してきた(例: チャット UI を入れて外すのを 6 回、永続化を 2 回入れて 2 回やめた)。
ADR は選んだ構成を持つが、試行の回数と失敗の連なりは持たない。git 履歴は持っているが、問いごとにまとまっておらず、戻した理由もほとんど残っていない。
オーナーから、AgentHub で使っている試行の記録(Trials)と実験レポートの仕組みを Shoppie にも入れたいと依頼があった(2026-10-05)。

## 決定
- `docs/trials/` に、ADR と同じ形(README の一覧表とテンプレート、1 問い 1 ファイル、連番)で試行を記録する
- 測って判断した実験は `docs/reports/` にレポートを書き、必ずどれかの問いの回に紐付ける
- コードを変えたら同じ作業の中で書く(`.claude/rules/activity-record.md`)。書き忘れは Stop hook(`.claude/hooks/trials-record-check.sh`)が 1 回差し戻す
- ADR とはマージしない。試行の結果として構成を選んだときは、trials の最後の回から ADR へリンクする
- 過去分は git 履歴から確認できる範囲で遡って起こした(14 問い・97 回)

## 理由
- 戻した変更とその理由が残っていないと、同じ試行を繰り返す。会話 UI のように「作って触って戻す」が多いプロダクトほど効く
- 「何回やって何がダメで、だから次どうしたか」を人に話せる形で残せる
- 仕組みは AgentHub で回っているものをそのまま使えるので、作る手間が小さい(個人開発で速く回す)

## 検討した代替案
| 案 | 良い点 | 見送った理由 |
|---|---|---|
| ADR に「試行」節を足す | 置き場が増えない | 1 つの問いが複数の ADR にまたがり(例: 件数と LLM の文脈は ADR-0011)、回数を通しで数えられない |
| 1 ファイルの台帳 | 追記が楽 | 問いが 14 件あり長くなる。ADR と同じ形のほうが探しやすい |
| git のコミット本文に任せる | 新しい作業が要らない | 問いごとにまとまらない。過去のコミットは理由をほとんど書いていない |

## 影響・見直し条件
- 変更のたびに 1 か所余分に書くことになる。hook が差し戻すので、問いを持たない変更でも 1 回止まることがある
- trials とコミット本文・ADR の内容が二重になって食い違いが増えたら、書く範囲を見直す
