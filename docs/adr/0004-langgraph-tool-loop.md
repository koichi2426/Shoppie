# ADR-0004: エージェントは LangGraph の「LLM 1 ノード＋ツールノード」で組む

- ステータス: 採用
- 日付: 2026-10-02（記録日。判断はそれ以前。[technical-qa.md](../technical-qa.md) から起こした）

## 背景
曖昧な発話 → ツール選択 → モール API → 再応答、というループが要る。
単発のプロンプトでは「JSON をがんばって出させる」だけになり、検索の責務がすべてプロンプトに乗る。

## 決定
LangGraph で次の最小構成にする（詳細は [langgraph-agent.md](../langgraph-agent.md)）。
- `llm_agent`: ツール選択か最終発話
- `tool`: Yahoo / 楽天 / Amazon の検索（並列可）
- 空の結果が続いたら打ち切る（無駄な再試行でトークンを使わない）

検索条件（価格帯・ソートなど）は StructuredTool + Pydantic のスキーマで拘束する。

## 理由
- モデルの賢さに頼るより、ツールの境界で推論を拘束する方が安定する
- モールごとの差（パラメータ・認証）にツール単位で追従できる

## 検討した代替案
| 案 | 良い点 | 見送った理由 |
|---|---|---|
| 単発の LLM 呼び出し | 単純 | 検索の責務がプロンプトに全部乗る |
| LLM は検索クエリ文字列だけ出し、サーバーが固定の API を叩く | LLM の出力が小さい | 拡張しにくく、モールの差に追従しにくい |
| 意図抽出・構造化・要約の専用ノードに分ける | 役割が明確 | グラフが増えるとデバッグが難しい。今は不要 |

## 影響・見直し条件
- ノードを増やすとデバッグが難しくなるので、最小構成を保つ
