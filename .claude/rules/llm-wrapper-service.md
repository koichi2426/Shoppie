# LLMラッパーサービス(必守)

詳細は `.claude/rules/llm-wrapper-service-guide.md`(`fastapi/backend/infrastructure/gateways/langgraph/**` 等作業時に paths でロード)。
目標: OpenAI/Anthropic等のLLM APIをラップし、複数ユーザー(エージェント)に自社サービスとして提供するバックエンドを、業界標準のステートレス構成で作る。

## 必守

- バックエンドはユーザー/エージェントごとに専用プロセスを立てない**ステートレス**にする。会話状態はRedis/RDB等の外部ストアに置く
- LLM APIキーはバックエンドの外に一切出さない。クライアントには自社発行の短命トークンのみ渡す
- 会話履歴は毎回DBから復元し、**直近ウィンドウに上限**を設ける(詳細: `.claude/rules/ai-agent-context-engineering.md`)
- 複数プロバイダ(OpenAI/Anthropic/Gemini/ローカルモデル)を統一インターフェースの裏に隠す(自前実装 or LiteLLM等)
- レート制限・課金は**リクエスト数ではなくトークン数**で計測する
- リトライ(指数バックオフ)・モデルフォールバック・サーキットブレーカーを実装する
- ストリーミングはSSEを使い、経路上の全プロキシバッファリングを無効化する
- 入力・出力の両方にガードレール(プロンプトインジェクション対策・PIIフィルタ)を通す

## 禁止

- ユーザー/エージェントごとに専用コンテナ・専用プロセスを常時起動すること
- DBに保存した全履歴をそのまま毎回 `messages[]` に詰め込むこと(上限・要約・RAGでの選択的注入が必須)
- プロバイダの生SDKをユースケース/画面のコードに直接書くこと
- 1リクエスト数だけでレート制限をすること(トークン数の異なるリクエストを同列に扱うと、実際のプロバイダ側TPM制限との整合が取れない)
- プロンプトエンド(フロント/アプリバイナリ)にAPIキーを直接埋め込むこと
- system promptへの指示だけでプロンプトインジェクション対策を終わらせること
