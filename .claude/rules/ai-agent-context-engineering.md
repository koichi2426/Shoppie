# AIエージェント文脈構築(必守)

詳細は `.claude/rules/ai-agent-context-engineering-guide.md`(エージェント/LLM呼び出し実装時に paths でロード)。
目標: LLMへ毎リクエスト渡すコンテキストを、ただの生ログではなく **キャッシュ・選択・圧縮** で組み立てる。

## 3原則

- **キャッシュ**: system prompt・ツール定義など不変部分はリクエストの先頭に固定し、prompt cachingの分だけコスト・レイテンシを稼ぐ
- **選択(RAG)**: 会話履歴は全部載せない。直近の短いウィンドウだけを生の文脈として送り、それより古い記憶は埋め込み検索で関連するものだけ注入する
- **圧縮(Compaction)**: 直近ウィンドウからも溢れた古いやり取りは要約して畳む(または長期記憶の検索に任せる)。生ログを無制限に蓄積しない

## 層を混同しない

「ChatGPT等は少数の巨大モデルに全ユーザーを相乗りさせる(continuous batching)」は**プロバイダ内部のLLM推論サーバー層**の話。外部からAPIを叩くだけのオーケストレーション層(プロンプトの組み立て・ツール呼び出し・会話状態管理を行う層)は、それに一切関与できないし、似ても似つかない。1テナント1コンテナ方式か共有ワーカープール方式かは、そのオーケストレーション層自体の別の設計論点であり、レート制限やコストの直接的な解決策ではない(詳細はguide参照)。

## 禁止

- 会話履歴(直近ウィンドウ)に**必ずデフォルトで有効な上限**を持たせないこと。env未設定なら無制限を許すような実装にしない
- 毎リクエスト全ツール定義をそのまま送ること。そのエージェント・その場面で有効なものだけに絞る
- 「あとで直す」前提で上限をひとまず0(無制限)にしたまま本番投入すること — 会話が伸びるほど1リクエストのトークン数・コスト・レート制限抵触頻度が急激に悪化する
